# Superweapon list (MO / rulesmo.ini)

Data source: `AutoLoadDev/ini/rulesmo.ini`

- **Section name**: `id=section` in `[SuperWeaponTypes]` (ids 0–134, no gaps, 135 total)
- **Name**: look up each section's `UIName=NAME:xxx` in the CSF translation table
- **Attached building**: the superweapon id appears in some building's `SuperWeapon=` /
  `SuperWeapon2=` /
  **`SuperWeapons=a,b,c`** (all three forms must be recognized)

## How the names were looked up

The CSF translation tables live in `AutoLoadDev/ini/`, three of them:

| File | Role | Name entries provided |
|---|---|---:|
| `stringtable10(单位名称).csf.txt` | **primary** | 1277 |
| `stringtable09(原版信息).csf.txt` | fallback (fills gaps of the primary) | 830 |
| `stringtable11(战役文本).csf.txt` | campaign text, no Name entries | 0 |

Three pitfalls when reading the tables, all actually hit:

1. **The prefix is case-insensitive**: the three tables use `name:` / `Name:` / `NAME:`
   respectively. Matching only one spelling drops entire tables' worth of entries (without `Name:`
   `SpyPlaneSpecial`'s `侦察机` cannot be found).
3. **The two tables have 33 same-name/different-value conflicts**, so a priority had to be decided.
   Measured by coverage:
   - Superweapon `UIName`: table 10 hits 93/135, table 09 adds only 2 more
     (`SpyPlaneSpecial` 侦察机 / `ForceShieldSpecial` 力场护盾)
   - so **table 10 wins, table 09 fills gaps**
   - 4 conflicts resolved in favor of table 10. Proof: `IronCurtainSpecial`'s
     `Name=Invulnerability` maps to table 10's "无敌"; table 09's "铁幕装置" is an MO-coined name

**Current coverage**: superweapon names **103/135**;
attached-building names **64/65** distinct buildings (109 attachment references in total, 108 of them
named).

**135** total, split into three groups (mutually exclusive, sum to 135):

| Group | Count | Criteria |
|---|---:|---|
| **Main table** | **94** | `SW.ShowCameo` is not false **and** (has a `UIName` or is attached to a building) |
| Internal helper types | 26 | no `UIName` **and** not attached to any building (pure placeholder sections) |
| Intentionally hidden | 15 | `SW.ShowCameo=false`, but has a name or is attached |

**Status column**:
- `**instant**` = takes effect on a single click, no map click needed (criteria in notes, "Appendix:
  instant-type superweapons")
- `**sustained**` = the `UseChargeDrain=yes` "long-duration" kind, filtered out by default via
  `DrainSupers=0`

## Priority / hiding syntax

Write `<section name>=<integer>` in `[SWSidebar]` of `MOExperience.ini`:

```ini
[SWSidebar]
; negative = hide this superweapon
SpyPlaneSpecial=-1
; 0 or omitted = show by default (priority 1000)
; positive = priority, smaller number comes first; same values sort by SuperWeaponType::ArrayIndex
NukeSpecial=10
ChronoSphereSpecial=20
; to push a default-shown superweapon to the very front, give it 1
IronCurtainSpecial=1
```

**The key name must match the "section name" column exactly (case-sensitive)**. One wrong letter
produces no error — it silently does nothing, because every unrecognized key in `[SWSidebar]` is
treated as a "superweapon ID" and collected into the priority table, adding an entry to the sidebar
that never lights up.

## Additional notes

### Not a single `Action=None`

All 135 superweapons have an `Action` key: `Custom` 125; `IronCurtain` 2;
`LightningStorm` 2; `ChronoSphere` / `ChronoWarp` / `ForceShield` /
`Nuke` / `ParaDrop` / `PsychicDominator` 1 each; **`None` 0**.

So the `Action=None` criterion in the "fires on click" test **never hits once** in this project; what
actually does the work is `Type ∈ {HunterSeeker, Battery}` together with `SW.UseAITargeting`.

### The 3 with `UseChargeDrain=yes` (sustained kind)

| Section name | Name | Type | ChargeToDrainRatio | RechargeTime |
|---|---|---|---|---|
| `BlasticadeSpecial` | Blast Barrier | **Firestorm** | .5 | 4 |
| `PsychicFlashSpecial` | Psychic Fire | Battery | .25 | 6 |
| `GoldenWindSpecial` | Golden Wind | Battery | .2 | 5 |

All three carry `ShowTimer=yes` + `SW.Unstoppable=yes`.

**Note that `BlasticadeSpecial`'s `Type` is `Firestorm`, not `Battery`** — it reaches the same effect
as `Battery` via `UseChargeDrain` + `ChargeToDrainRatio`,
but does **not** satisfy the "instant" criterion. So it is "sustained but not instant" and gets
filtered by `DrainSupers=0`.

### Still without names

- **27 have no `UIName` key**: 26 of them are also not attached to any building (i.e. the "internal
  helper types"). The exceptions are `ReproCashFix` (attached to `FAREPR`) and `TickTrapSpawn`
  (attached to `YATUNL`) — no name but actually referenced by a building, so by cameo they belong to
  the main table / intentionally hidden.
- **1 attached building has no name to be found**: `F_ERESB`. It is itself a placeholder building —
  `Name=Fake Elite Reserves (Do Not Use)`, `UIName=NAME:DUMMYDUMMY`,
  `Selectable=no`, `Insignificant=yes`, `AIBuildThis=no`.
  It exists only to give `EliteReservesMessage` an attachment point; it is not a building the player
  can see, so having no name is normal — **not a missing translation-table entry**.
- **2 superweapons have a `UIName` but neither CSF finds them**:
  `IonStormSpecial` (`NAME:UltimaWeapon`), `CrateDropSpecial` (`NAME:CrateDrop`).
  The binary `ra2md.csf` in the same directory is a non-standard CSF v3 variant; per the "don't
  reverse-engineer the game" rule it was not parsed, so these two names are **unknown, not made up**.
- **1 CSF entry exists but its content is clearly wrong**: `PsychicBeaconSpecial` →
  `距离心灵信标准备完成时间：` — a timer string put into `UIName`,
  presumably a problem with the mod data itself.
- The Chinese entries of `HunterSeekerSpecial` / `GearChangeSpecial` contain parentheses or a newline
  (`猎杀机器人（最多5架）` = "Hunter-Killer Robots (max 5)" /
  `工厂停产维护\n资金增加$3000` = "Factory maintenance shutdown\nFunds +$3000") — exactly as in the
  mod data.

### Three pitfalls when scanning the ini (all actually hit)

1. **The `2` in `SuperWeapon2=` is not the plural `s`**. Matching with `SuperWeapons?` misses the
   entire second slot, and misjudges the superweapons attached to it as "unattached" (this once made
   the count 25 short).
2. **`SuperWeapons=` is a comma-separated list**. Taking only the first token misses the other
   superweapons on the same building (all 18 of them, e.g. Radiation Quad Airstrike, are in the
   plural form).
3. **Don't reuse `cur` left over from the previous section in a loop**. When rescanning the file,
   forgetting to reset the "current section" makes the entire attachment table point at the same
   section name (this once showed every superweapon's "attached building" as `VariableNames`).
