# Правила каталогов
Локальные правила, написанные для агентов.

| Каталог | Назначение | Что сюда кладётся | Что запрещено |
|---|---|---|---|
| `src/` | Исходники, участвующие в сборке | `.c`/`.cpp`, на которые ссыляются команды сборки | Пробы, эксперименты, остатки `.inj` |
| `dist/` | **Единственный каталог релиза** | DLL — результат сборки, образец ini (хуки встроены в DLL секцией `.syhks00`, развёртывание `.inj` не требуется — см. `src/core/SyringeHooks.cpp`; `dist/*.inj` оставлен только для аудита) | Промежуточные файлы, экспериментальные файлы |
| `build/` | Промежуточные артефакты компиляции/отладки | `.o`, дампы `.asm` | Залипшие DLL, тестовый код |
| `test/` | Тесты и разовые эксперименты | Пробы, эксперименты с раскладкой, временные файлы анализа | Всё, участвующее в сборке, долгоживущие файлы |
| `notes/` | Заметки | Справочные материалы, накопленный опыт, записи-референсы, выводы по пробам и т.п. |  |
| `other/` | Прочее (пользовательское) | Это каталог пользователя: картинки и файлы для публикации | Агент не работает с этой папкой |

Правила:

1. Команды сборки **напрямую указывают на `dist/`**; для выкатки наружу файлы берутся только из `dist/`.
2. В `tools/` — только скрипты; тулчейн может лежать в `tools/mingw/mingw32/bin` (`/tools`
   игнорируется `.gitignore` и в репозиторий не попадает). Если его нет на машине, скрипты сборки ищут
   `%MOE_MINGW%` → `tools/` → `../AutoLoadDev/tools`
   → `PATH` в этом порядке, поэтому при смене машины или чужой клонировке скрипты править не нужно.
   Для `references/` всегда используется
   `../AutoLoadDev/references`.
3. Цепочка сборки и пути к подключаемым заголовкам — чистый ASCII; комментарии в исходниках и
   документация могут быть китайскими.
   **`.bat` — строго чистый ASCII + CRLF** (cmd.exe читает их в OEM-кодовой странице: китайский
   превращается в кракозябры, а LF съедает первый символ строки).
4. Сторонние проекты фиксируются минимальной записью-референсом (адрес, вызовы, выводы) — целые файлы
   в репозиторий не сводятся.
5. `src/` разбит на подкаталоги по функциональным доменам:
   | Каталог | Ответственность | Модули |
   |---|---|---|
   | `core/` | Жизненный цикл и инфраструктура | `MOExperience` (слой координации), `SyringeHooks`, `Lang`, `MOEVersion.h`, `EngineAddr.h` |
   | `gui/` | Отрисовка и интерфейс | `VecText`/`MsgText`/`GdiText`/`ToolTip`, `SWPanel`/`PowerDisplay`/`Icon`/`PcxImage`, `FullMap`/`ScaleBar`/`PiP`/`GridView`/`Shot`/`PauseView`/`ChatEdit`/`LineEdit`, `EscMenu`/`PlayerColor`, `icons.rc`/`IconRes.h` |
   | `order/` | Приказы и мышь/клавиатура | `SmartOrder`/`SmartArea`/`FuzzyAttack`/`AttackMove`/`Aggressive`/`TreeChop`/`TypeSelect`/`MindSelect`/`PatrolCircle`/`RallyPath`/`AirWay`/`OrderThrottle` + общие утилиты приказов `OrderUtil` |
   | `sidebar/` | Боковая панель, производство и супероружия | `BuildQueue`/`SWSBar`/`SWSTest`/`RepairAll`/`SideScroll`/`SidebarSkin` |
   | `preview/` | Превью размещения и радиусы | `DeployPreview`/`PlacementPreview`/`PlaceScatter`/`WeaponRange` |
   | `perf/` | Тайминги и ограничение частоты | `FrameCap`/`GameSpeed` |
   | `misc/` | Мелкие патчи движка и уведомления | `Observer`/`WaypointCap`/`MegaListCap`/`NoApproach`/`PvpNotice` |

   Имена файлов модулей совпадают с именами секций ini; заголовки подключают друг друга по голому имени,
   на этапе компиляции это разрешается через
   `-Isrc -Isrc\core -Isrc\gui -Isrc\order -Isrc\sidebar -Isrc\preview -Isrc\perf -Isrc\misc`.
   **При добавлении/удалении подкаталога меняется ровно одно место**: `SRCINC` в `build-common.bat`
   (от него выводятся и `CXXFLAGS`, и `$inc` для сканирования зависимостей). Список исходников больше не
   пишется вручную — при сборке сканируется `src\**\*.cpp`
   и генерируется `obj\sources.txt`, поэтому добавление/переименование/перемещение `.cpp` не требует
   правок скриптов сборки.
